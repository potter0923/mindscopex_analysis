# J-Lens 트랙 — 다음 순서 1번·2번 (2026-10-04)

## 현재 위치

| | | |
|---|---|---|
| 1 | 생각 없이 답하면 함정에 빠진다 | ✅ |
| 2 | 생각할 시간을 주면 정답으로 돌아온다 | ✅ |
| 3 | 내부 원인을 찾아 억제한다 | ❌ |
| 4 | 다른 함정에도 통한다 | ❌ |

1·2는 9B에서 확인됨 (`hagendorff_crt` 150문항, 무추론 함정 22개 → 추론 시 22개 전부 복구).

3이 막힌 이유는 탐색 공간(feature 8만 × 레이어 × 토큰)이 너무 넓어서다. J-Lens는 범인을 지목하는 도구가 아니라 **수색 범위를 좁히는 지도**로 들어왔다.

## 비어 있는 자리

10/2에 2B에서 J-Lens와 logit lens를 비교해 **0.35 대 0.10**이 나왔으나, 차이의 구간에 0이 들어가 우위를 확정하지 못했다.

**현상은 9B에서 가장 깨끗한데, 비교는 2B에서만 했다.**

## 맡을 부분

### 1번 — 9B에서 J-Lens vs logit lens

105문항 적합 / 45문항 측정, 같은 위치에서 두 렌즈 비교.

**앞으로 J-Lens를 계속 쓸지가 여기서 갈린다.** 지금은 "나아 보이지만 확정 못 함" 상태라 후속 작업을 얹기 애매하다. 신호만으로 원인은 주장하지 않는다.

### 2번 — 새 함정 문항

`hagendorff_crt`는 2023년 공개 데이터라 재사용에 한계가 있다. "다른 작성자" 조건은 설계자 본인이 만들면 성립하지 않으므로 제가 쓰는 쪽이 맞다. 1번 가설을 2번 문항으로 확인하는 순서가 된다.

## 코드

| | |
|---|---|
| `src/mindscopex_analysis/jlens.py` | 공식 구현(`anthropics/jacobian-lens`) 어댑터. Qwen3.5 지원 확인돼 수식 재구현 없음 |
| `experiments/jobs/jlens_item1.py` | 1번 실행 본체. 적합 → 측정 → 비교 → JSON |
| `tests/test_jlens.py` | 46개 |

**짚어둘 것 하나.** `hagendorff_crt`의 답은 `" $20.0"` / `" $40.0"` 꼴이라 **첫 토큰이 둘 다 `" $"`로 같다.** 렌즈는 한 토큰만 읽으므로 그대로 두면 150문항 전부가 측정 불가가 된다. 두 답이 처음 갈라지는 위치를 찾아 그 자리를 읽도록 고쳐서 150/150 측정 가능해졌다. 새 문항을 쓸 때도 반영할 조건이다.
